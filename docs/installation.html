📦 Installation

Drop-in install for any of the six supported platforms. Same jar, different entrypoints.

1. Pick the right jar

There's only one jar, georestrict-2.1.0.jar. The same file works on:

  • Bukkit 1.16+ (Spigot, Paper, Purpur, ...)
  • Folia 1.20+ — detected at runtime, region-aware scheduler is used automatically
  • BungeeCord, Waterfall
  • Velocity 3.2.0+
Where to put it depends on your topology. If you have a proxy, install on the proxy. The plugin blocks at the network edge, which is the only place to actually reject a connection. Installing on backend servers is a fallback for direct-connect servers.

2. Install

Bukkit / Paper / Folia / Spigot

shell 
cd /path/to/server
cp georestrict-2.1.0.jar plugins/
./start.sh   # or systemctl restart minecraft

BungeeCord / Waterfall

shell 
cd /path/to/proxy
cp georestrict-2.1.0.jar plugins/
./start.sh

Velocity

shell 
cd /path/to/velocity
cp georestrict-2.1.0.jar plugins/
./start.sh

3. Verify the install

On startup you should see this in the console:

console 
[GeoRestrict] GeoRestrict v2.1.0 starting...
[GeoRestrict] GeoRestrict enabled.

And a config file at plugins/GeoRestrict/config.yml (Bukkit) or plugins/GeoRestrict/config.yml (Bungee/Velocity).

4. Set up the Worker (recommended)

The plugin talks to a Cloudflare Worker. Out of the box it points at the public one at geoprotect.demonzdev.workers.dev, which works but is shared. If you'd rather not share IPs with the rest of the internet:

  1. Fork or copy worker/src/index.js from this repo.
  2. Deploy it: npx wrangler deploy in the worker/ directory.
  3. Set GATEWAY_TOKENS as a Worker secret.
  4. Update gatewayUrl and gatewayToken in your plugin config.
If you set GATEWAY_TOKENS on the Worker, requests without a matching gatewayToken are rejected with HTTP 401. The default config has an empty token — leave it that way when using the public Worker, or set one to lock down your private one.

Updating

Replace the jar, restart, done. Config keys you don't have are added with sane defaults. Keys you have are kept. configVersion tracks schema version, not plugin version, and bumps only when the file layout changes.

Uninstalling

Delete the jar, delete plugins/GeoRestrict/, restart. Nothing is written outside that directory.
