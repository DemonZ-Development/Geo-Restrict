🔧 How It Works

A detailed look at how GeoRestrict processes every player connection.

Connection Flow

  1. Player connects — A player attempts to join your server. GeoRestrict hooks into the login event.
  2. Check local cache — The plugin first checks its local IP cache for a previous lookup result.
  3. Cache hit — If a valid cached result exists, rules are evaluated instantly with zero network latency.
  4. Cache miss — If no cache entry is found (or it has expired), the plugin queries the Cloudflare Worker gateway.
  5. API lookup — The gateway tries ip-api.com as the primary source and automatically falls back to ipinfo.io if needed.
  6. Cache the response — The lookup result is stored locally on your server for the configured TTL period, preserving player privacy.
  7. Evaluate rules — Rules are checked in order: Country → ASN/ISP → VPN/Proxy. The first matching rule determines the outcome.
  8. Allow or kick — If a restriction matches, the player is kicked with the configured message. Otherwise, they join normally.
  9. Discord notification — If a webhook is configured, a rich embed is sent to your Discord channel with connection details.

Privacy

GeoRestrict is designed with privacy first. All IP lookup data is stored exclusively on your server in a local cache file. No player data is ever sent to, or stored on, any third-party cloud service or database.

The only external requests made are to the IP geolocation APIs during a cache miss — and even those go through a privacy-respecting Cloudflare Worker gateway.

🔒

Enable discord.maskIp in your config to partially redact player IP addresses in Discord webhook messages (e.g. 192.168.***. ***).

Folia Support

Folia uses a region-aware multi-threaded scheduling model instead of a single main thread. GeoRestrict auto-detects Folia at startup and switches to region-aware task scheduling automatically.

No extra configuration is required — just drop the plugin into your Folia server's plugins/ folder and it will work correctly.

Private Subnet Bypass

Connections from private / local IP ranges (e.g. 127.0.0.1, 192.168.x.x, 10.x.x.x) are automatically bypassed — they are never sent to the API and are always allowed. This ensures localhost and LAN connections are never blocked.
