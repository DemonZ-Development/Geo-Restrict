🛠️ Troubleshooting

Real problems, with the actual fix.

All my players get kicked with "Geo verification is temporarily unavailable"

That's the kickMessageLookupFailure message. It means the Worker is unreachable and you have blockOnLookupFailure: true (the new default). Two things to check:

  1. From the server console, try curl -I https://geoprotect.demonzdev.workers.dev/?ip=8.8.8.8. If that times out, the issue is network egress, not the plugin.
  2. If you deployed your own Worker, double-check the gatewayToken matches GATEWAY_TOKENS on the Worker side. Mismatches return 401 and the plugin treats that as a lookup failure.

Quick fix: blockOnLookupFailure: false in your config. Re-enable when the network is healthy.

Players using OVH / Hetzner / DigitalOcean are getting blocked

That's the ISP keyword scanner doing its job — OVH, Hetzner, DigitalOcean are all in the default vpnKeywords list because they sell VPSes that are commonly used for game-server bot farms.

Options:

  • Remove the specific keyword from vpnKeywords if you know your player base is on that host.
  • Set vpnCheckEnabled: false to disable keyword detection entirely (boolean flags from the provider still work).
  • Combine: keep the keyword, but ALLOWLIST the specific players with georestrict.bypass + OP on the backend server.
My proxy-installed plugin isn't blocking anyone

Check which jar is where. If you put the plugin on the backend Bukkit server and your players connect through Bungee/Velocity, the connection arrives at the backend with the proxy's IP — the proxy is the one seeing the player's actual IP at the network edge. Either:

  • Install on the proxy (recommended), or
  • Install on the backend AND enable proxy-protocol or ip-forwarding: true in Bungee/Velocity so the backend sees the real IP, not the proxy's.

You can install on both — the backend will see a second check after the proxy's, and the player gets denied at the proxy if they get past it.

The plugin isn't loading on Folia

Check the startup log for the line GeoRestrict v2.1.0 starting.... If you don't see it, the jar isn't in the plugins/ folder. If you see the line but errors follow, paste the full stack trace — the Folia scheduler adapter is reflection-based, so it can fail on renamed methods if your Folia build is wildly different from upstream.

The cache file is huge

100k entries in the default JSON cache is ~5–10 MB. If you're seeing gigabytes, you have a runaway log somewhere — probably a config file that mtime-changes every read. Run /georestrict cachestats to see entry count and oldest age. If entries keep growing without bound, run /georestrict purgecache and watch the log for a config watcher loop.

Update check is spamming the log every 6 hours

It only logs when a new version is actually available. If you're seeing repeated update lines, the version comparison is broken — but that was fixed in 2.1.0. Update to the latest and the spam should stop.

Discord webhook is broken / 400 errors

Three usual causes:

  1. Webhook URL is wrong or revoked. Regenerate in Discord, paste the new URL, /georestrict reload.
  2. Network egress to discord.com is blocked (some hosting providers). Check from the server console: curl -I https://discord.com/api/webhooks/...
  3. You have an empty field in discord.fields. The plugin drops empty fields, but a malformed YAML {name: ""} used to throw. Make sure each field has a name and a value.
