🛠️ Troubleshooting

Diagnostic tips and solutions for common GeoRestrict issues.

1. Players Bypassing Restrictions (LAN/Localhost)

If you or your team connect to the server and do not get blocked, even when connecting from a blocked country, check the following:

  • Private Subnet Exemption: GeoRestrict has built-in subnet filtering. Any IPv4 range under RFC 1918 (such as 192.168.x.x, 10.x.x.x, 172.16.x.x) and IPv6 loopback (::1) are automatically allowed through without a geo-lookup to prevent locking out local connections.
  • Bypass Permissions: Verify if the player has the georestrict.bypass permission. Operators (OPs) have this permission by default in Bukkit and Velocity.

2. Discord Webhook Notifications Not Firing

If players are being kicked but your Discord channel is not receiving notifications, follow these validation steps:

  • Double check the discord.webhook URL in config.yml. Ensure it is correct and not wrapped in conflicting brackets.
  • Confirm that the server has outbound internet connectivity. If the server is in a restricted sandbox environment, it might block HTTPS requests to discord.com.
  • Review the console logs for HTTP connection exceptions or error codes returned by the Discord API.

3. High Connection Latency or Gateway Timeouts

If logins are taking longer than usual or you see timeout errors in the server logs:

  • The default connection timeout is 3000ms. If the Cloudflare Worker gateway is slow, you can adjust this value using the connectionTimeoutMs setting in the configuration file.
  • Verify the health and response times of your deployed Cloudflare Worker gateway. You can monitor request durations on the Cloudflare Dashboard.

4. Out-of-Date Cache Data

If you've recently changed rules or if a player's IP location changed but they're still blocked or allowed:

  • Player location results are cached locally in plugins/GeoRestrict/geo_cache.json (or the respective directory for Velocity/BungeeCord) for 30 days by default.
  • You can run the /georestrict purgecache command to clear the local cache file and force fresh lookups on the next connection.
  • Alternatively, adjust cacheTtlDays in your config to a lower value (e.g., 7 or 14 days).

5. BungeeCord / Velocity Sub-Server Bypass

If you run a proxy network (BungeeCord/Velocity) and have the GeoRestrict plugin installed on backend Bukkit servers:

  • Important: Ensure IP forwarding is properly configured in your proxy config (ip_forward: true for BungeeCord, player-info-mode: forwarding for Velocity) and enabled on the backend Spigot/Paper servers (bungeecord: true in spigot.yml).
  • Without IP forwarding, the backend servers will see all player connections originating from the proxy's local IP address (typically 127.0.0.1), which automatically bypasses geographic restrictions.
